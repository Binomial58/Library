## 偏角の厳密比較ライブラリ

整数座標 `(x, y)`（原点 `(0, 0)` を除く）について、浮動小数点を一切使わずに、原点から見た偏角（x軸正方向を0とした反時計回りの角度）の大小関係を厳密に判定するライブラリ。

`atan2` ベースの実装は、座標が大きい（`~10^9`）場合に異なる方向でも角度差が浮動小数点の精度限界に迫るほど接近しうる「killerケース」で壊れる。これを回避するために、外積の符号と半平面判定だけで比較を行う。

`geometry.hpp`（`Real = double` 前提の浮動小数点幾何ライブラリ）とは型が異なるため、別ファイルとして独立させている。

### 前提・型

- 点は `std::pair<long long, long long>`（`x, y`）で表す
- 制約目安：`|x|, |y| <= 10^9` 程度まで安全（`cross` の計算が `long long` の範囲に収まる）。それ以上大きい座標を扱う場合は `__int128` への変更を検討する
- `(0, 0)` は非対応（偏角が定義できない）。呼び出し側で事前に除外しておく

### 使い方

```cpp
#include "polar_angle_sort.hpp"
using namespace polar_angle_lib;

vector<Point> points = {{1, 0}, {0, 1}, {-1, 0}, {0, -1}};
sort(points.begin(), points.end(), cmp); // 反時計回り[0°, 360°)順
```

### 提供する関数

#### `ll cross(Point a, Point b)`

外積 `a.x * b.y - a.y * b.x` を返す。

- `> 0`：`a` から `b` へ反時計回りに角度差 `(0°, 180°)` の範囲にある
- `< 0`：`a` から `b` へ時計回りに `(0°, 180°)` の範囲にある（＝ `b` から `a` が反時計回り）
- `== 0`：`a, b` は同一直線上（同じ方向 or 正反対の方向、どちらもあり得る。詳細は下記「注意点」参照）

#### `bool ah(Point p)`（半平面判定、内部で使用）

```
ah(p) = 1  if p.y < 0, または (p.y == 0 かつ p.x < 0)
ah(p) = 0  それ以外（p.y > 0、または p.y == 0 かつ p.x > 0）
```

角度 `[0°, 180°)` を `ah=0`、`[180°, 360°)` を `ah=1` とする分類。境界は `0°` が `ah=0` 側、`180°` が `ah=1` 側に入る（半開区間）。

#### `bool cmp(Point a, Point b)`

`std::sort` 等に渡す比較関数。「`a` の偏角が `b` より真に小さいか」を返す。

1. `ah(a) != ah(b)` なら、`ah(a) < ah(b)` を返す（半平面が違えばそれで確定）
2. `ah(a) == ah(b)` なら、`cross(a, b) > 0` を返す（同じ半平面内では外積の符号で比較）

これで、偏角 `[0°, 360°)` の反時計回り順の厳密な狭義全順序（strict weak ordering）になる。`std::sort(points.begin(), points.end(), cmp)` で使う。

#### `bool sameAngle(Point a, Point b)`

「`a` と `b` が厳密に同じ方向（偏角が完全一致）か」を判定する。

```
sameAngle(a, b) = (ah(a) == ah(b)) && (cross(a, b) == 0)
```

### 注意点（このライブラリの一番のハマりどころ）

**`cross(a, b) == 0` だけでは「同じ方向」と判定してはいけない。** 外積が0になるのは `a, b` が同一直線上にあることを意味するだけで、これは

- 同じ方向（偏角差0°）
- 正反対の方向（偏角差180°）

の両方を含む。例：`a=(1,0)`（0°）と `b=(-1,0)`（180°）は `cross(a,b) = 1*0 - 0*(-1) = 0` だが、方向は正反対。

「同じ方向かどうか」を判定したい場面（偏角ソート後の同順位グループ化、クエリでの『回転量ゼロ』判定など）では、必ず **`ah` の一致も一緒に確認する**（＝ `sameAngle` を使う）こと。`cross(a,b)==0` 単体でこの判定に流用すると、正反対のペアを誤って「同じ方向」扱いしてしまうバグを埋め込む。

### 計算量

- `cross` / `ah` / `cmp` / `sameAngle`：いずれも `O(1)`
- `std::sort(points.begin(), points.end(), cmp)`：`O(n log n)`（`n` は点数、`cmp` 1回が `O(1)` なので通常の比較ソートの計算量に一致）
- 「典型的な使い方」全体（ソート＋タイグループ前計算＋クエリ）：前計算 `O(n log n)`、各クエリ `O(1)`

### 典型的な使い方（偏角の範囲に入る点数を数える、のようなクエリ問題）

1. 点集合を `cmp` でソートし、各点の元のインデックスも一緒に並べ替える（`argsort` + `apply_order` 等）。座標が重複する点があり得るので、座標そのものをキーにしたマップで rank を引くのは避け、元のインデックスに対応する配列で直接 rank を持つ
2. ソート後の隣接ペアについて `sameAngle(P[i], P[i+1])` で同順位（タイ）グループを判定し、各位置 `i` について「そのタイグループの左端 `L[i]`・右端 `R[i]`」を前計算しておく
3. クエリ `(A, B)` では、それぞれの rank `ai, bi` を求め、
   - `sameAngle(P[ai], P[bi])`（同じ方向）または `ai > bi`（ラップ不要）なら、範囲は `[L[bi], R[ai]]`
   - それ以外（ラップが必要）なら、範囲は `[0, R[ai]] ∪ [L[bi], n-1]`（要素数 `n - L[bi] + R[ai] + 1`）
